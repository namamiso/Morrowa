# Morrowa App Drawer 編集モード v2 — 要件・設計

Status: **確定(2026-07-12)**。§10.42 のロールバック(v1 全撤去)を受けた再設計。
v1 の失敗分析は `Morrowa_AppDrawer_編集モード_実装計画.md` §10.40〜10.42 を正本とする。

## 0. 決定事項(2026-07-12 ユーザー確定)

| 論点 | 決定 |
|---|---|
| 編集の入口 | **明示的な編集モード**。入口は**アイコン長押しポップアップの「編集」項目**(AOSP ポップアップへのガード付きフック1つ) |
| 並び替え UI | **ドロワー上で直接ドラッグ**(RecyclerView `ItemTouchHelper`) |
| フォルダ作成・追加 | **複数選択→「フォルダにまとめる」/「フォルダへ追加」**(ドラッグ重ね生成は v2 スコープ外)。新規作成時は**名前入力ダイアログ**(空確定なら「フォルダ」) |
| 順序モデル | **統合順序を維持**(フォルダをアプリの間の任意位置に置ける = 旧要望A) |
| 新規インストールアプリ | 統合順序の**末尾に追加**(未編集=DrawerOrder 空ならアルファベット表示のまま) |
| 編集の中断 | **変更がある時だけ破棄確認ダイアログ**、変更なしなら即閉じ。回転は編集継続(状態は ViewModel 保持) |
| 編集中のフォルダのタップ | **タップ=選択**。フォルダ内編集(内部並び替え・除外・リネーム)と解除は、フォルダ1つ選択時のアクションから |

## 1. 設計原則(§10.42 より、全フェーズで拘束)

1. Morrowa 独自 UX は **AOSP 内部機構を曲げず、Morrowa 所有のレイヤーで実装**する。AOSP 側に置いてよいのはガード付きフックのみ。
2. ドラッグは `DragController` ではなく **`ItemTouchHelper`** 等のプラットフォーム標準機構。
3. 状態は「**DB → 単一 Flow → 表示**」の一方向。楽観二重書き・one-shot シード等の競合源を設けない。
4. 順序モデル等のロジックは**純 Kotlin に切り出し、単体テストを実装より先に**書く。
5. 統合の関門はコンパイル成功ではなく**受け入れ条件の実機確認**。

## 2. 要件

### R1. 編集モード
- 入口: **アイコン長押しポップアップの「編集」項目**(ドロワー内のアプリアイコンのポップアップに追加。ホーム画面のポップアップには出さない)。編集モード中は:
  - アプリのタップ起動、AOSP 長押しポップアップ、ドラッグでのホーム配置を**無効化**(編集オーバーレイが全て遮る)
  - 「完了」で一括確定。戻る/閉じる時、**変更があれば破棄確認ダイアログ**、なければ即閉じ。回転では編集を継続
- 検索中・Work タブ・Private Space は編集対象外(パーソナルの A-Z リストのみ)。

### R2. 統合順序の並び替え
- フォルダとアプリは**単一のシーケンス**。長押しドラッグで任意位置へ移動(フォルダ自体の移動も同一操作 = 旧要望Bを包含)。
- ドラッグ中は標準のライブプレビュー(`ItemTouchHelper` の move)。
- 再起動後も順序保持。
- 新規インストールアプリは**末尾に追加**(rank 未付与のアプリは末尾にアルファベット順でぶら下がる)。

### R3. フォルダ操作(すべて編集モード内)
- タップで**選択トグル**(アプリ・フォルダ共通、複数選択可)。選択内容に応じてアクションバーに操作が出る:
  - アプリのみ選択 → 「フォルダにまとめる」(**名前入力ダイアログ**、空確定なら「フォルダ」。フォルダは最初に選択したエントリの位置に生成、メンバーは表示順で格納)/「フォルダへ追加」(既存フォルダを選ぶ)
  - フォルダ1つ選択 → 「フォルダを編集」(サブ画面: 内部並び替え `ItemTouchHelper`・メンバー除外・リネーム)/「解除」(中身がフォルダのあった位置に展開)
- メンバー除外したアプリは**フォルダの直後**に出る。編集の結果メンバーが1個以下になったフォルダは**自動解除**(残メンバーがフォルダの位置に出る)。
- フォルダのネスト(フォルダ選択で「まとめる」)は**不可**(アクション非活性)。
- AOSP `Folder` ビューは**編集には一切使わない**(v1 の J1 系の轍。閲覧時の開閉は従来どおり AOSP)。

### R4. 永続化
- 単一テーブル `DrawerOrder(key TEXT PK, rank INT)`(`app:<componentKey>` / `folder:<id>`)+既存 `Folders`/`FolderItems`。
- **編集セッション中はメモリのみ**、「完了」で1トランザクション一括コミット。閲覧中に書き込みは発生しない。

### R5. スコープ外(v2 では作らない)
- ドラッグ重ねでのフォルダ生成/追加(操作性が安定したら第3フェーズ候補)
- ドロワー→ホームへのドラッグ配置との連携(従来機能は通常モードでそのまま)
- 検索結果・Work タブ上の編集、Home フォルダとの相互運用、クラウド同期

## 3. アーキテクチャ

### 3.1 編集オーバーレイ(核心の分離)
編集モードは、AllApps の上に被せる **Morrowa 所有の全画面オーバーレイ**(`AbstractFloatingView` として DragLayer に追加、ALL_APPS state のまま)で実装する。

- 独自 `RecyclerView` + `GridLayoutManager`(列数・アイコンサイズ・パディングは `DeviceProfile` から流用し、見た目の連続性を再現)+ 独自アダプタ。
- `ItemTouchHelper` はこの独自 RecyclerView にのみアタッチ。
- **編集中、AOSP の AllApps ビュー・アダプタ・`AlphabeticalAppsList` には一切触れない**(下に隠れているだけ)。完了 → DB コミット → オーバーレイを閉じる → 閲覧側は Flow 経由で新順序を表示。
- v1 で問題化した「DiffUtil と drag の衝突」「state 遷移」「DragController の DropTarget 優先順位」は構造的に発生しない。

### 3.2 状態管理
- `DrawerEditViewModel`: 編集セッションの単一状態 `EditState(entries: List<DrawerEntry>, selection: Set<Key>, editingFolderId: Int?)` を `StateFlow` で保持。
- セッション開始時に現表示順のスナップショットを**同期的に**取得(= v1 の one-shot シード競合は構造的に存在しない)。
- すべての操作(move / group / addToFolder / disband / removeFromFolder / rename)は純 Kotlin の `DrawerOrderModel` への関数適用。UI は状態の純関数。

### 3.3 純 Kotlin モデル+テスト先行
```
DrawerOrderModel(entries) {
  fun move(fromIndex, toIndex): DrawerOrderModel
  fun groupIntoFolder(keys, title): DrawerOrderModel   // 最初の選択位置に folder エントリ
  fun addToFolder(keys, folderId): DrawerOrderModel
  fun disband(folderId): DrawerOrderModel               // その位置に展開
  fun moveInFolder(folderId, from, to): DrawerOrderModel
  fun insertNewApps(keys): DrawerOrderModel             // Q2 の方針に従う
}
```
Android 依存ゼロ。実装前に上記全操作の単体テストを書く(空リスト・単一要素・端インデックス・重複キー・未知キーを含む)。

### 3.4 閲覧側(AOSP 側に入れる唯一のロジック)
- `LawnchairAlphabeticalAppsList` に「`DrawerOrder` が空なら従来表示(フォルダ上部ブロック+アルファベット)、非空なら rank-merge 表示」の**読み walk のみ**追加(v1 G1 の読み経路の知見は再利用可。書き込み側の競合源が無いので v1 の G 系バグは再現しない)。
- fast-scroll セクションは v1 G1 と同じ「連続アプリ項目の頭文字変化で区切る」方式。

### 3.5 AOSP 側フック(ガード付き・最小)
1. アイコン長押しポップアップへの「編集」項目追加(ドロワー内アイコン限定のガード付き。Lawnchair のポップアップカスタマイズ機構が使えるならそちら優先)
2. オーバーレイ表示中の背面タッチ遮断(`AbstractFloatingView` の標準機構で足りる見込み)

上記以外に AOSP ファイルへの変更が必要になった場合は、実装を止めて本ドキュメントに追記・判断を仰ぐ(§10.42 原則1)。

## 4. フェーズ分割と受け入れ条件

| フェーズ | 内容 | 受け入れ条件(実機) |
|---|---|---|
| P0 | `DrawerOrderModel` 純 Kotlin +単体テスト一式 | 全テスト green(実機不要) |
| P1 | DB(`DrawerOrder` v4)+閲覧側の読み walk | DrawerOrder 空の状態で従来表示と完全一致。手動で rank を入れると反映・再起動後保持 |
| P2 | 編集モード入口+オーバーレイ+並び替え+完了/キャンセル | 編集→ドラッグ並び替え→完了で反映・再起動後保持。キャンセルで無変更。編集中に起動/ポップアップ/ホーム遷移が起きない |
| P3 | 複数選択→フォルダ生成/追加/解除 | 選択位置にフォルダ生成、解除で位置展開、いずれも再起動後保持 |
| P4 | フォルダ編集ビュー(内部並び替え・除外・リネーム) | 開き直し・再起動後も順序保持。メンバーが消えない |

各フェーズ: 実装 → コンパイル → **実機受け入れ確認 → コミット+push**(§10.32.2 / §10.42 原則5)。

## 5. 決定ログ(2026-07-12、質問形式で確定)

- **Q1. 編集モードの入口** → **アイコン長押しポップアップに「編集」項目**(ドロワー内限定、フック1個)。
- **Q2. 新規インストールアプリの挿入位置** → **末尾に追加**。
- **Q3. 編集中断の扱い** → **変更がある時だけ破棄確認**、なければ即閉じ。回転は継続、プロセス死は破棄。
- **Q4. 編集中のフォルダのタップ挙動** → **タップ=選択**。フォルダ内編集・解除はフォルダ1つ選択時のアクションから。
- **Q5. フォルダ新規作成時の名前** → **作成時に名前入力ダイアログ**(空確定なら「フォルダ」)。
- **Q6. DB バージョン**: ロールバックで v3 に戻ったため、v2 実装では v3→v4 として `DrawerOrder` を追加(v1 の v4/v5 とは別物として扱う。テスト機はデータ消去済み前提)。
