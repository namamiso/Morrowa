# Morrowa 仕様書 v0.1

作成日: 2026-06-02  
位置付け: Morrowa の初期仕様書。Lawnchair fork に存在する機能のうち、残すもの、変更するもの、追加するものを整理し、Android ホームランチャーとして ToDo、Habit、アラーム、外部ウィジェット配置を生活導線に統合するための MVP 仕様を定義する。

---

## 1. プロジェクト概要

Morrowa は、Android のホーム画面そのものを「アプリを開く場所」から「今日を動かす場所」へ変えるパーソナルホームランチャーである。

Lawnchair fork をベースに、ランチャーとしての基本機能を保ちながら、ToDo、Habit、アラーム、外部ウィジェット配置をホーム体験の中心に組み込む。

### 1.1 基本方針

| 項目 | 内容 |
|---|---|
| アプリ名 | Morrowa |
| 種別 | Android ホームランチャー |
| 実装方針 | Lawnchair を fork して構築 |
| 保存方式 | 完全ローカル保存 |
| クラウド同期 | MVP では採用しない |
| 共有 / 複数ユーザー | MVP では採用しない |
| 将来公開 | Play ストア公開を視野 |
| 最初の最適化対象 | Galaxy S22 Ultra |
| 端末環境 | Android 16 / One UI 8.0 を主対象 |
| 重視点 | 軽さ、変更容易性、美しさ、行動導線 |

### 1.2 コンセプト

```text
スマホを使う場所から、自分を動かす場所へ。
```

Morrowa は、生活管理アプリをホーム画面の外側に置くのではなく、ホーム画面そのものに行動の入口を置く。

- ToDo、習慣、アラームを統合した、自分専用の美しいホームランチャーを作る。
- UI は壁紙に溶け込ませるだけでなく、独立した道具として美しく成立させる。
- 入力負荷、画面の重さ、後戻りしづらい実装を避ける。
- 情報量よりも、毎日触る導線の気持ちよさを優先する。
- まず自分の端末に最適化し、将来的には他者も使える形へ広げる。

### 1.3 MVP の到達点

MVP では、以下を満たす状態を目指す。

- Android の既定ホームとして使える。
- アプリ一覧、ホーム配置などのランチャー基本動作が壊れていない。
- Home / Habit / ToDo / Widget Blank の 4 論理ページを持つ。
- Habit と ToDo をホーム導線上で直接扱える。
- Habit の達成履歴を草カレンダーで確認できる。
- ToDo と Habit に任意のアラームを紐づけられる。
- 未達習慣通知で、今日できていない習慣に気づける。
- すべての主要データが端末内のローカル DB に保存される。
- 手動 JSON エクスポート / インポートでバックアップできる。

### 1.4 OSS 由来機能の扱い

この仕様書は、Lawnchair fork を単なる実装素材ではなく、既存 OSS ランチャー機能の取捨選択対象として扱う。

Morrowa の機能は、以下の 3 分類で定義する。

| 分類 | 意味 |
|---|---|
| 残すもの | Lawnchair にすでに存在する基本ランチャー機能を、Morrowa でも維持する |
| 変更するもの | Lawnchair に存在する機能を、Morrowa の行動導線に合わせて挙動や表示を変える |
| 追加するもの | Lawnchair には存在しない、Morrowa 独自の生活管理機能を新規に入れる |

分類ごとの初期方針:

| 分類 | 対象 |
|---|---|
| 残すもの | Android 既定ホーム、アプリ一覧、ホーム配置、フォルダ、外部ウィジェット配置、基本設定導線 |
| 変更するもの | ホームページ構成、横スワイプ挙動、最後にいたページへの復帰、アイコン表示、長押しメニュー、Dock / QSB 非表示、Workspace 下部グリッド統合 |
| 追加するもの | Habit 画面、ToDo 画面、Widget Blank 画面、Habit 草カレンダー、ToDo / Habit アラーム、未達習慣通知、ゴミ箱、ローカル DB、JSON バックアップ |

## 2. プロダクト原則

### 2.1 採用する原則

- 完全自作ランチャーではなく Lawnchair fork をベースにする。
- ランチャー基盤の再発明ではなく、Task / Habit / Alarm の統合体験に工数を使う。
- Lawnchair にある基本ランチャー機能は、Morrowa の価値と衝突しない限り残す。
- Morrowa の生活導線に必要な場合だけ、既存機能の挙動を変更する。
- ToDo、Habit、アラーム、通知、バックアップは Morrowa 独自機能として追加する。
- MVP ではクラウド同期を入れない。
- MVP では外部ウィジェットより、ランチャー内部パネル UI を優先する。
- ただしカレンダー表示は外部カレンダーウィジェットの配置余地を残す。
- ユーザーは単一人物を前提にする。
- SaaS 的な汎用管理画面を増やさない。
- 毎日見る画面として圧迫感を避ける。

### 2.2 MVP で採用しないもの

| 項目 | 理由 |
|---|---|
| クラウド同期 | MVP の軽さとローカル完結を優先 |
| 複数端末同期 | 同期設計が重くなる |
| 共有 / チーム利用 | 単一ユーザー向けでは不要 |
| タグ | 入力負荷が増える |
| サブタスク | MVP には不要 |
| 高度な統計画面 | 草カレンダーで十分 |
| Google カレンダー連携 | 外部ウィジェットに任せる |
| 内蔵カレンダー | MVP では作らない |
| スヌーズ | 行動導線を複雑にする |
| JSON マージインポート | MVP では全置換のみ |

## 3. ランチャー全体構成

### 3.1 ページ構成

Morrowa は 4 つの論理ページを持つ。横スワイプで移動し、左右どちらにも循環できる。

| 順番 | ページ名 | 役割 |
|---:|---|---|
| 1 | Home | Lawnchair の通常ホームページ |
| 2 | Habit | Morrowa 専用の習慣管理画面 |
| 3 | ToDo | Morrowa 専用の ToDo 管理画面 |
| 4 | Widget Blank | Lawnchair の通常ホームページ。初期状態は空白 |

循環順:

```text
Home -> Habit -> ToDo -> Widget Blank -> Home
```

逆方向:

```text
Home -> Widget Blank -> ToDo -> Habit -> Home
```

### 3.2 ページレイヤー方針

Morrowa の 4 ページは、Lawnchair の通常ホームページ群へすべてを混ぜ込むのではなく、Morrowa 側の論理ページとして扱う。

| 論理ページ | 実体 | 扱い |
|---|---|---|
| Home | Lawnchair 通常ページ | アプリ、フォルダ、ウィジェットを置ける |
| Habit | Morrowa 専用固定画面 | アプリ、フォルダ、ウィジェットは置けない |
| ToDo | Morrowa 専用固定画面 | アプリ、フォルダ、ウィジェットは置けない |
| Widget Blank | Lawnchair 通常ページ | アプリ、フォルダ、ウィジェットを置ける。初期状態はまっさら |

Home と Widget Blank は、Lawnchair の通常ページを 2 ページ分使う。Habit と ToDo は通常ホームページとしては扱わず、Morrowa 専用 UI として表示する。

### 3.3 ページ移動仕様

| 項目 | 仕様 |
|---|---|
| 移動方法 | 横スワイプ |
| ループ | 有効 |
| 左右端 | 存在しない |
| ページインジケータ | 表示しない |
| タブ | 表示しない |
| 画面端タップ移動 | 採用しない |
| 初回起動 | Home を表示する |
| ホーム復帰 | 最後にいたページへ戻る |
| ロック解除後 | 最後にいたページへ戻る |
| アプリから戻る | 最後にいたページへ戻る |

### 3.4 最後にいたページの保存

`last_page_type` を軽量設定として保存し、ホーム表示時に復元する。初回起動時、または保存済みページが存在しない場合は Home を表示する。頻繁な DB 書き込みを避けるため、DataStore または SharedPreferences 相当を使う。

```text
launcher_state
- last_page_type
- updated_at
```

`last_page_type`:

```text
HOME
HABIT
TODO
WIDGET_BLANK
```

## 4. Home 画面仕様

### 4.1 基本方針

Home は通常ランチャーに近い配置画面とする。アプリアイコン、フォルダアイコン、ウィジェットを配置できるが、検索バーと Dock は持たない。

| 項目 | 仕様 |
|---|---|
| アプリアイコン配置 | 可能 |
| フォルダ配置 | 可能 |
| ウィジェット配置 | Home では通常ランチャー仕様に従う |
| 検索バー / QSB | 持たない |
| Dock / Hotseat | 表示・操作対象としては使わない |
| 旧 Dock / QSB 領域 | 通常 Workspace グリッドに統合し、下部 2 行もアプリ・フォルダ・ウィジェットを配置可能にする |
| アイコン透明化 | 採用する |
| ホームから削除 | 長押しメニューから実行し、Undo を出す |

### 4.2 アイコン透明化

アプリアイコンまたはフォルダアイコンを透明化できる。透明化されたアイコンは通常時には完全に見えないが、タップ領域は残り、タップ起動も有効なままとする。

| 対象 | 透明化 |
|---|---|
| アプリアイコン | 可能 |
| フォルダアイコン | 可能 |
| ウィジェット | 対象外 |
| Habit / ToDo の項目 | 対象外 |

透明化時の扱い:

| 要素 | 仕様 |
|---|---|
| アイコン画像 | 非表示 |
| ラベル | 非表示 |
| タップ領域 | 残す |
| タップ起動 | 有効 |
| 長押し操作 | 残す |
| アクセシビリティ名 | 残す |
| 配置情報 | 維持する |
| 編集モード中 | 透明化済みアイコンを薄く表示する |

### 4.3 長押しメニュー

アプリまたはフォルダを長押しすると、小さなメニューを表示する。

通常アイコンの場合:

```text
透明化
ホームから削除
```

透明化済みアイコンの場合:

```text
透明解除
ホームから削除
```

| メニュー項目 | 動作 |
|---|---|
| 透明化 | アイコン画像とラベルを非表示にする |
| 透明解除 | アイコン画像とラベルを再表示する |
| ホームから削除 | ホーム配置から削除する。アプリ自体はアンインストールしない。削除後は Undo を出す |

### 4.4 Dock / QSB 仕様

Morrowa は Dock と QSB を持たない。旧 Dock / QSB 領域は通常 Workspace グリッドに統合し、Home と Widget Blank の下部 2 行もアプリ、フォルダ、ウィジェットの配置対象にする。

| 項目 | 仕様 |
|---|---|
| Dock | 表示しない |
| QSB / 検索バー | 表示しない |
| Hotseat オブジェクト | Launcher 内部互換用に残す |
| Hotseat 高さ | 0 とし、表示・操作対象としては使わない |
| Hotseat カスタマイズ設定 | MVP では表示しない |
| 既存 Dock アイテム | MVP では DB に残したまま非表示にする |
| Dock -> Workspace 下部行 migration | 将来タスクとして扱う |

## 5. Habit 画面仕様

### 5.1 基本構成

Habit 画面は習慣管理専用画面である。上から順に以下を配置する。

1. 日付 / habit day 表示
2. GitHub 草風カレンダー
3. 選択日の対象習慣一覧
4. 習慣追加 FAB

### 5.2 習慣基本仕様

| 項目 | 仕様 |
|---|---|
| 記録形式 | チェック式のみ |
| 名前 | 必須 |
| メモ | 任意 |
| メモの Markdown | 許可 |
| 文字数制限 | 名前・メモともに100文字まで |
| 作成時必須項目 | 名前、頻度ルール |
| アラーム | 任意。作成後に設定してもよい |
| 編集確定 | 保存ボタンを押すまで確定しない |
| 日付境界 | 4:00 |
| habit day 基準 | JST 固定 |
| チェック | 1日1回 |
| 並び順 | 完全手動 |
| 一覧表示 | 手動順 |
| アーカイブ | 履歴を残して通常一覧から消す |
| 削除 | ゴミ箱へ移動し、30日後に完全削除 |

### 5.3 頻度ルール

習慣ごとに以下のいずれかを設定する。

| ルール | 内容 |
|---|---|
| 毎日 | 毎 habit day 対象 |
| 毎週 | 複数曜日指定 |
| 毎月 | 複数日指定 |

詳細:

- 未選択での保存は不可。
- 毎週ルールでは複数曜日を選択できる。
- 毎月ルールでは複数日を選択できる。
- 31日指定は、その日が存在しない月では対象外。
- 頻度変更時は履歴として保存する。
- 新ルールは指定された `effective_from_habit_day` 以降に適用する。
- 過去の履歴は現在のルールで再解釈しない。

### 5.4 habit day 判定

習慣だけ 4:00 境界を使う。

| 実時刻 | habit_day |
|---|---|
| 2026-06-02 03:59 | 2026-06-01 |
| 2026-06-02 04:00 | 2026-06-02 |
| 2026-06-02 23:59 | 2026-06-02 |

### 5.5 草カレンダー

Habit 画面には GitHub 草風カレンダーを表示する。

| 項目 | 仕様 |
|---|---|
| 表示範囲 | その年の1月1日から12月31日 |
| 週の始まり | 日曜日 |
| 曜日ラベル | 略式表記 |
| 月ラベル | 上部に間引き表示 |
| 年端の空白 | 空白マスを許可 |
| 色 | 0%は灰色、100%は濃緑、中間は線形 |
| 達成率 | その日の対象習慣のうち達成済みの割合 |
| タップ範囲 | マスそのもの |
| 長押し | 何もしない |
| 未来日選択 | 不可 |
| 未来日チェック | 不可 |
| 過去日選択 | 可能 |
| 過去日チェック編集 | 可能 |

操作:

- マスをタップすると、その日の対象習慣一覧を表示する。
- チェック操作で草の色を即更新する。
- 過去日編集もその日のマスに即反映する。
- 対象習慣が0件の日は 0% の灰色で表示する。

### 5.6 習慣一覧

| 項目 | 仕様 |
|---|---|
| 対象 | 選択日に実行対象となる習慣 |
| 並び順 | 現在の `sort_order` 順 |
| 表示項目 | 名前のみ |
| メモ表示 | 詳細編集内 |
| 選択日表示 | 一覧上部に小さく表示 |
| 対象0件 | 空欄でよい |

### 5.7 習慣操作

| 操作 | 仕様 |
|---|---|
| 追加 | FAB から追加 |
| チェック切り替え | Habit をタップすると選択日のチェック ON / OFF を切り替える |
| 編集 | 長押しメニューから編集画面または編集ドロワーを開く |
| 並べ替え | 右端のつまみでドラッグ |
| 長押しメニュー | 編集、アラーム設定、アーカイブ、削除 |
| アーカイブ | 長押しメニューからアーカイブを選び、確認メニューで確定して通常一覧から消す |
| アーカイブ確認 | 「アーカイブしますか？」を表示し、確定時のみアーカイブ |
| 削除 | 長押しメニューから削除を選び、確認メニューで確定してゴミ箱へ移動 |
| 削除確認 | 「削除しますか？」を表示し、確定時のみ削除 |
| スワイプ操作 | 採用しない |
| Undo | Habit 削除 / アーカイブでは表示しない |
| アーカイブ解除 | 管理画面から復帰 |

## 6. ToDo 画面仕様

### 6.1 基本構成

ToDo 画面はタスク管理専用画面である。習慣とは分離し、ToDo だけに集中する。

上から順に配置する。

1. 今日の日付
2. ToDo 一覧
3. ToDo 追加 FAB
4. 必要に応じてゴミ箱入口またはメニュー

### 6.2 ToDo 基本仕様

| 項目 | 仕様 |
|---|---|
| タイトル | 必須 |
| メモ | 任意 |
| メモの Markdown | 許可 |
| 文字数制限 | タイトル・メモともに100文字まで |
| 作成時必須項目 | タイトル |
| 予定日 | 任意 |
| 日付境界 | 0:00 |
| 完了状態 | 持たない |
| 表示条件 | 削除されていない ToDo |
| 並び順 | 完全手動 |
| 優先度 | `sort_order` で表現 |
| サブタスク | なし |
| タグ | なし |
| アラーム | 1件につき最大1つ。任意。作成後に設定してもよい |
| 編集確定 | 保存ボタンを押すまで確定しない |
| 削除 | 不要になったらゴミ箱へ移動 |
| ゴミ箱 | 30日保持して完全削除 |

### 6.3 予定日の扱い

予定日は任意である。ToDo 一覧の表示条件を支配しない。

| ToDo 種別 | 扱い |
|---|---|
| 予定日なし | 通常タスク |
| 予定日あり | 日付チップを表示 |
| 今日の ToDo | 視覚的に少し強調する |
| 未来の ToDo | 手動順に従って表示 |
| 過去日の ToDo | 削除せず、表示上だけ少し強調する |

重要な原則:

```text
予定日は判断材料であり、並び順の支配者ではない。
```

### 6.4 ToDo 操作

| 操作 | 仕様 |
|---|---|
| 追加 | FAB から追加 |
| 編集 | タップで詳細編集 |
| 詳細表示 | メモ、予定日、アラーム設定を表示 |
| 並べ替え | 右端のつまみでドラッグ |
| 長押しメニュー | 編集、アラーム設定、削除 |
| 削除 | 長押しメニューから削除を選び、確認メニューで確定してゴミ箱へ移動 |
| 削除確認 | 「削除しますか？」を表示し、確定時のみ削除 |
| スワイプ削除 | 採用しない |
| Undo | ToDo 削除では表示しない |
| 復元 | ゴミ箱から末尾へ復元 |

### 6.5 完了状態を持たない理由

MVP の ToDo は「完了したら不要になるもの」として扱う。完了チェックを持つと、完了済み一覧、履歴、復活、期限切れなどの設計が増えるため、MVP では削除と復元だけにする。

## 7. Widget Blank 画面仕様

### 7.1 基本方針

Widget Blank は、外部カレンダーウィジェットなどを置くための空白ページである。Home と同じ Lawnchair の通常ホームページとして扱い、ウィジェット、アプリアイコン、フォルダを自由に配置できる。

| 項目 | 仕様 |
|---|---|
| 初期状態 | 何も置かない |
| ページ実体 | Lawnchair の通常ホームページ |
| 主用途 | 外部カレンダーウィジェット配置 |
| 外部ウィジェット | 配置可能 |
| アプリアイコン | 配置可能 |
| フォルダ | 配置可能 |
| ショートカット | 配置可能 |
| 内蔵カレンダー | 作らない |
| Google カレンダー連携 | MVP では作らない |

### 7.2 カレンダー方針

Morrowa は MVP では内蔵カレンダーを持たない。カレンダーを置くべき場所には Widget Blank を用意し、外部ウィジェットに任せる。

| 項目 | 扱い |
|---|---|
| 独自カレンダー UI | 不採用 |
| ローカル予定表 DB | 不採用 |
| Google カレンダー同期 | 不採用 |
| 外部カレンダーウィジェット | 採用 |
| ToDo の予定日 | 維持 |

## 8. アラーム / 通知仕様

### 8.1 基本方針

Morrowa は ToDo と Habit に紐づく任意のアラームを持つ。さらに、今日できていない習慣数を知らせる未達習慣通知を持つ。

| 種別 | 仕様 |
|---|---|
| ToDo アラーム | ToDo 1件につき最大1つ。設定は任意 |
| 習慣アラーム | Habit 1件につき最大1つ。設定は任意 |
| 習慣アラームの日付 | 習慣ルールを参照して計算 |
| 未達習慣通知 | 今日できていない習慣数を通知 |
| 通知方式 | MVP では通常通知から始める |
| 通知タップ | 対象画面へ直接遷移する |
| アラーム音 | MVP では独自音を持たず、Android 標準の通知音に任せる |
| スヌーズ | なし |
| アラーム操作 | 停止のみ |
| 停止後の状態 | ToDo / Habit は未完了のまま |
| 再起動後 | 保存済みアラームを DB から再登録する |

### 8.2 未達習慣通知

未達習慣通知は、今日できていない習慣数を知らせる通知である。アプリ内で完全無効化する設定は MVP では持たない。不要な場合は端末側の通知設定で止める。

通知時刻は MVP では 20:00 の 1回をデフォルトとする。

| 項目 | 仕様 |
|---|---|
| デフォルト時刻 | 20:00 |
| 通知回数 | 1日1回 |
| 通知対象 | その habit day で未達の習慣 |

通知タップ時の遷移:

| 通知 | タップ時 |
|---|---|
| ToDo アラーム | ランチャーを開き、ToDo 画面へ直接遷移する |
| Habit アラーム | ランチャーを開き、Habit 画面へ直接遷移する |
| 未達習慣通知 | ランチャーを開き、Habit 画面へ直接遷移する |

### 8.3 Android 権限上の注意

アラームと通知は Android 側の権限制約を受ける。MVP 設計時に以下を確認する。

| 項目 | 注意点 |
|---|---|
| 正確なアラーム | `SCHEDULE_EXACT_ALARM` または `USE_EXACT_ALARM` の検討が必要 |
| Android 14 以降 | `SCHEDULE_EXACT_ALARM` は多くの新規インストールで既定不許可になりうる |
| 通知 | Android 13 以降は `POST_NOTIFICATIONS` 実行時権限が必要 |
| Play ストア公開 | アラーム、通知の用途説明を明確にする必要がある |

参考:

- Android Developers, Schedule alarms: https://developer.android.com/develop/background-work/services/alarms
- Android 14 exact alarm changes: https://developer.android.com/about/versions/14/changes/schedule-exact-alarms
- Notification runtime permission: https://developer.android.com/develop/ui/compose/notifications/notification-permission
- Android 10 fullscreen intent behavior changes: https://developer.android.com/about/versions/10/behavior-changes-10
- Android 14 fullscreen intent summary: https://developer.android.com/about/versions/14/summary

## 9. ゴミ箱仕様

### 9.1 基本仕様

| 項目 | 仕様 |
|---|---|
| 対象 | ToDo、Habit |
| 保持期間 | 30日 |
| 日数計算 | JST |
| 削除タイミング | アプリ起動時、または定期メンテナンス時 |
| 並び順 | 捨てた日時の新しい順 |
| 残り日数表示 | 小さく「あとN日」表示 |
| 丸め方式 | 切り上げ |

### 9.2 ゴミ箱内操作

| 操作 | 仕様 |
|---|---|
| 詳細表示 | タップで詳細 |
| 復元 | 復元ボタンで復元 |
| ToDo 復元先 | ToDo 一覧の末尾 |
| Habit 復元先 | Habit 一覧の末尾 |
| 完全削除 | 確認メニューで確定した場合のみ完全削除 |
| 完全削除確認 | 「完全に削除しますか？」を表示する |
| 完全削除後 Undo | 表示しない |
| 自動削除 | 30日経過した項目を自動削除対象にする |
| 複数選択 | MVP では採用しない |

## 10. データ設計

### 10.1 基本方針

Morrowa は完全ローカル保存とする。Room を前提に、ToDo、Habit、アラーム、ランチャー状態を管理する。

将来の移行やバックアップを妨げない最低限の時刻カラムは持つ。ただし MVP では同期用の重いカラムは持たない。

持つ:

- `id`
- `created_at`
- `updated_at`
- `deleted_at`
- JSON 側の `schema_version`

持たない:

- `server_id`
- `sync_state`
- `dirty_flag`
- `remote_updated_at`

### 10.2 `todos`

```text
todos
- id
- title
- memo nullable
- scheduled_date nullable
- sort_order
- is_deleted
- deleted_at nullable
- created_at
- updated_at
```

### 10.3 `habits`

```text
habits
- id
- name
- memo nullable
- sort_order
- is_archived
- is_deleted
- deleted_at nullable
- created_at
- updated_at
```

### 10.4 `habit_rule_history`

```text
habit_rule_history
- id
- habit_id
- rule_type
- weekdays_mask nullable
- monthdays_json nullable
- effective_from_habit_day
- created_at
```

`rule_type`:

```text
DAILY
WEEKLY
MONTHLY
```

### 10.5 `habit_completions`

```text
habit_completions
- habit_id
- habit_day
- done
- checked_at
```

候補主キー:

```text
PRIMARY KEY (habit_id, habit_day)
```

### 10.6 `alarm_rules`

```text
alarm_rules
- id
- owner_type
- owner_id
- enabled
- time_of_day
- sound_type nullable
- created_at
- updated_at
```

`owner_type`:

```text
TODO
HABIT
```

### 10.7 `alarm_schedules`

```text
alarm_schedules
- id
- alarm_rule_id
- next_fire_at
- scheduled_system_id nullable
- status
- created_at
- updated_at
```

`status` 候補:

```text
SCHEDULED
FIRED
CANCELED
FAILED
```

### 10.8 `habit_reminder_settings`

```text
habit_reminder_settings
- id
- times_json
- created_at
- updated_at
```

アプリ内で完全無効化を持たない方針なら `enabled` は持たない。

### 10.9 ランチャー配置

Home / Widget Blank のアプリ、フォルダ、ウィジェット配置は Lawnchair 標準 DB を使う。
Morrowa 独自 DB には Home / Widget Blank の配置情報を持たない。

透明アイコン状態は、可能なら Lawnchair 標準 DB 側の拡張カラムとして持つ。調査の結果、既存 DB 拡張が危険な場合は Morrowa 側の独自保存へ退避する。

配置情報として Morrowa 独自 DB に持たないもの:

```text
app icon placement
folder placement
widget placement
cell position
span
```

Morrowa 側で持つ可能性があるもの:

```text
last_page_type
transparent item state fallback
```

### 10.10 ランチャーページ

Morrowa の論理ページは 4ページ固定の定数として扱う。
Home と Widget Blank は Lawnchair 通常ホームページを 2ページ分使う。
Habit / ToDo 専用画面の差し込み場所は、Lawnchair の Workspace / ページ管理構造を調査してから確定する。

Morrowa 独自 DB には、原則として `launcher_pages` テーブルを持たない。
ページ復帰に必要な `last_page_type` は Launcher DB ではなく、DataStore / SharedPreferences 相当の軽量設定に保存する。

```text
last_page_type:
- HOME
- HABIT
- TODO
- WIDGET_BLANK
```

## 11. JSON エクスポート / インポート仕様

### 11.1 基本方針

MVP から手動エクスポートとインポートを持つ。形式は JSON。主目的は機種変更とローカルバックアップである。
対象は Morrowa の ToDo / Habit 関連データに限定し、Home / Widget Blank の配置情報や透明アイコン状態は含めない。

| 項目 | 仕様 |
|---|---|
| エクスポート | 手動 |
| インポート | MVP から対応 |
| 形式 | JSON |
| MVP のインポート方式 | 全置換のみ |
| マージ | 将来対応 |
| 目的 | 機種変更、ローカルバックアップ |
| 配置情報 | 対象外 |
| 透明アイコン状態 | 対象外 |

### 11.2 全置換インポート

MVP では、インポート時に既存データを全て置き換える。

対象:

- ToDo
- Habit
- habit rule history
- habit completions
- alarm rules
- alarm schedules のうち復元可能なもの
- habit reminder settings
- trash items

注意:

- インポート前に確認ダイアログを出す。
- 既存データは失われる。
- Android の system alarm id は端末依存のため、インポート後に再スケジュールする。
- Home / Widget Blank のアプリ、フォルダ、ウィジェット配置は対象外。
- 透明アイコン状態は対象外。
- `last_page_type` などのランチャー状態は対象外。

### 11.3 JSON メタ情報

```json
{
  "app": "Morrowa",
  "schema_version": 1,
  "exported_at": "2026-06-02T00:00:00+09:00",
  "device_note": "optional",
  "data": {}
}
```

## 12. OSS 機能別 MVP 範囲定義

MVP の範囲は、Lawnchair fork にすでにある機能を基準に、残すもの、変更するもの、追加するものとして定義する。

### 12.1 OSS 由来で残すもの

| 領域 | 内容 |
|---|---|
| Lawnchair fork ベース | 採用 |
| Android 既定ホーム | 残す |
| アプリ一覧 | 残す |
| ホーム配置 | アプリ、フォルダ、ウィジェット配置を残す |
| フォルダ | 残す |
| Hotseat オブジェクト | 内部互換用に残す。表示・操作対象としては使わない |
| 外部ウィジェット配置 | Home / Widget Blank で残す |
| 基本設定導線 | Launcher として必要な範囲で残す |
| アプリ起動 | 残す |
| ホームからの削除 | アンインストールではなく配置削除として残す |

### 12.2 OSS 由来から変更するもの

| 領域 | 変更内容 |
|---|---|
| ページ構成 | Home だけでなく、Home / Habit / ToDo / Widget Blank の 4 論理ページにする |
| ページレイヤー | Home / Widget Blank は Lawnchair 通常ページ、Habit / ToDo は Morrowa 専用固定画面にする |
| 横スワイプ | 4 論理ページを循環移動できるようにする |
| ホーム復帰 | 最後にいたページへ戻る |
| Home | 通常ランチャー機能を保ちつつ、透明アイコンを追加する |
| アイコン表示 | アプリ / フォルダアイコンを透明化できるようにする |
| 長押しメニュー | 透明化 / 透明化解除 / ホームから削除を追加または整理する |
| Dock / QSB | 表示せず、Hotseat は内部互換用に高さ 0 で残す |
| Workspace | 旧 Dock / QSB 領域を通常グリッドに統合し、下部 2 行もアプリ・フォルダ・ウィジェット配置可能にする |
| Hotseat カスタマイズ設定 | MVP では表示しない |
| 既存 Dock アイテム | MVP では DB に残したまま非表示にする。Workspace 下部行への migration は将来タスクにする |
| Widget Blank | Home と同じ Lawnchair 通常ページとして扱い、初期状態だけ空白にする |

### 12.3 Morrowa で追加するもの

| 領域 | 内容 |
|---|---|
| Habit 画面 | 追加、編集、手動並び、アーカイブ、削除 |
| Habit ルール | 毎日、毎週、毎月 |
| habit_rule_history | 正式採用 |
| Habit completions | 1日1回チェック |
| 草カレンダー | 達成習慣数の濃淡表示 |
| ToDo 画面 | 追加、編集、手動並び、削除 |
| ToDo 予定日 | 任意 |
| ToDo 完了状態 | 持たない |
| ToDo / Habit アラーム | 採用 |
| 未達習慣通知 | 採用 |
| ゴミ箱 | 30日後完全削除 |
| ローカル DB | ToDo、Habit、履歴、通知を保存。Home / Widget Blank の配置情報は Lawnchair 標準 DB に任せる |
| JSON エクスポート | 採用 |
| JSON インポート | 全置換のみ採用 |

### 12.4 MVP から外す

| 領域 | 理由 |
|---|---|
| クラウド同期 | 重い |
| 複数端末同期 | 重い |
| 共有機能 | 単一ユーザー向けでは不要 |
| Google カレンダー連携 | 外部ウィジェットに任せる |
| 内蔵カレンダー | 不採用 |
| カレンダーイベント DB | 不要 |
| タグ | 不要 |
| サブタスク | 不要 |
| スヌーズ | 不要 |
| JSON マージインポート | 将来対応 |
| ダイナミックカラー | 将来対応 |
| 高度な統計画面 | MVP では草カレンダーで十分 |
| ページインジケータ | 不要 |
| タブ UI | 不要 |

## 15. 設計メモ

Morrowa は、単にタスクを表示するアプリではない。ホーム画面という毎日何度も触れる場所に、行動の入口と生活の軌道を置くアプリである。

そのため、機能追加よりも、操作の軽さと視界の静けさを優先する。予定日は ToDo を縛る鎖ではなく、判断の小さな札として扱う。習慣は 4:00 境界で生活実感に寄せ、履歴は `habit_rule_history` で過去の状態を守る。

Widget Blank は空白ではなく、外部ウィジェットを迎えるための余白である。Home は完全なミニマリズムではなく、透明化できる通常ランチャーとして扱う。見えないアイコンは消えたのではなく、そこに置かれた静かな入口である。
