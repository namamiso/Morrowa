# Morrowa 議事録: UI 修正4件の調査と実装計画 (2026-07-26)

統括: Claude (Fable 5) / 調査: サブエージェント2名(並列) / 実装: Codex 予定

## 依頼内容

1. ToDo の文字が太く大きい → Habit と同じに
2. ToDo のメモが1行のみで見切れても放置 → 表示上のみ折り返し
3. Habit / ToDo のゴミ箱が背景透過で見づらい → 透明度のみ調整したすりガラス背景
4. Habit のハンバーガーメニューが長押しと同じ仕様なら、ドラッグ並び替えに置き換え

## 調査結果(要点)

### ① ToDo の文字
- **本文(アイテムのタイトル)は実は Habit と同一の 18sp**。「太く大きい」の主因は:
  - ヘッダー「ToDo」が 32sp **Bold** 純白(Habit は 26sp Medium `0xFFE6E8E1`)
  - 文字色が全体に純白 `Color.White`(Habit はやや落ち着いた `0xFFE6E8E1`)
  - カードの角丸・内パディング・行間隔が Habit より大きい
- 本文 18sp は触らない(下げると Habit より小さくなる)。

### ② ToDo のメモ
- **メモ(memo)はそもそも一覧に描画されていない**(編集ダイアログとバックアップのみ)。見切れているのは `maxLines = 1` + `Ellipsis` の**タイトル**(ToDoScreen.kt:257-258)。
- 編集ダイアログは singleLine 入力(改行は入らない)ため、「表示上のみ折り返し」は表示側の変更だけで完結。
- 対応は2案: (a) タイトルの maxLines/Ellipsis を撤廃して折り返し(最小)、(b) 加えてメモをタイトル下に折り返し表示(TrashScreen に既存の Column パターンあり)。→ **ユーザー確認事項**。

### ③ ゴミ箱の背景
- Habit/ToDo とも共通の `TrashContent` を使い、呼び出し側から `Color.Transparent` を渡しているのが原因(HabitScreen.kt:64 / ToDoScreen.kt:52)。背景を塗る Box は既にあり、**渡す色を変えるだけで直る**構造。
- 「透明度のみいじったすりガラス」= 既存パネル群(`0xCC1A1A1A`)と同系の半透明ダークの alpha を上げた `0xF2`(約95%)を専用定数 `TrashBackground` として渡す。本物のバックドロップブラーは Workspace ページ内 ComposeView という制約上、壁紙まではぼかせず費用対効果が低いため不採用。
- **同根の追加バグ発見**: ゴミ箱の全画面 Box がタッチを消費しておらず、**ゴミ箱表示中に下の一覧のタップ/長押しが突き抜けて発火する**。背景不透明化と同時にイベント消費を追加する(見た目だけ直すと「見えないのに押せる」が残るため必須)。

### ④ ハンバーガーメニュー
- **完全に冗長と確定**: ハンバーガーの onClick(HabitScreen.kt:466-467)と長押しの onLongClick(:417)は同一の `menuExpanded = true` で、同じ DropdownMenu(:479)を開く。差分ゼロ。ToDo 側は既にハンバーガー無し(長押しのみ)の「あるべき形」。
- ドラッグ並び替えの土台は想定以上に揃っている:
  - `sortOrder` カラムは habits / todos 両テーブルに**既存**、クエリも `ORDER BY sortOrder ASC` 済み → **Room マイグレーション不要**
  - ドラッグ並び替えライブラリ `sh.calvin.reorderable:3.1.0` が**導入済み**で、設定画面に完全な使用例あり(PositionalReorderer.kt ほか)
  - 不足は書き込み経路のみ: DAO の一括 sortOrder 更新 + Repository の `reorderHabits` + ViewModel の `moveHabit`

## 実装計画(1フェーズ=1コミット)

- **Phase 1 (依頼①)**: ToDo の文字スタイルを Habit と統一
  - ヘッダー 32sp Bold → 26sp Medium、純白 → `0xFFE6E8E1`(テーマ onSurface・空状態・アイコン tint 含む)
  - 角丸 20/16dp → 14/12dp、ヘッダー内 h18/v14 → h14/v8、画面パディング 24 → 28dp、アイテム間隔 12 → 8dp
  - アイテム内パディングは v16 → **v12**(ToDo はチェックボックス/IconButton が無く行が薄くなりすぎるため、Habit の v10 там倣わず中間値)
  - 受入: 差分が ToDoScreen.kt のみ。本文 18sp・期限 14sp は不変
- **Phase 2 (依頼②)**: タイトルの maxLines=1 / Ellipsis を撤廃し折り返し表示(+ユーザー選択によりメモの一覧表示を追加)
  - 受入: 長いタイトルが複数行で全文表示される。高さ固定が無いことは調査で確認済み
- **Phase 3 (依頼③)**: ゴミ箱背景を `TrashBackground = 0xF21A1A1A`(専用定数)に変更 + 全画面 Box にタッチ消費を追加
  - 受入: 下の一覧が透けない・タップが突き抜けない。BackupScreen(引数設計の共有先)に影響なし
- **Phase 4 (依頼④)**: ハンバーガー IconButton をドラッグハンドル(`Icons.Rounded.DragHandle` + `longPressDraggableHandle`)に差し替え、`rememberReorderableLazyListState` + `ReorderableItem` で並び替え、DAO/Repository/ViewModel に永続化経路を追加
  - 本体の長押しメニューは維持(機能は失わない)
  - 展開中カレンダーがある場合のドラッグ見た目は実装時に検証し、必要なら展開中はドラッグ抑止
  - 受入: 並び替えが DB に永続化され再起動後も維持。マイグレーション無し(DB version 据え置き)
- **Phase 5**: 独立レビュー → コミット → 実機検証手順の提示

## ユーザー決定 (2026-07-26)

1. **依頼②の対象は一覧ではなく編集ダイアログのメモ欄**(「一覧の話ではなく一回タッチした後の編集画面での話」)。ToDoEditDialog のメモ欄が singleLine=true で1行見切れになっているのが実体。→ Phase 2 は編集ダイアログのメモ欄を折り返し表示(singleLine 撤廃、改行文字は入力時に除去して「表示上のみ改行」を維持、100文字上限は維持)に変更。一覧のタイトル maxLines=1 は苦情対象外なので触らない。HabitEditDialog のメモ欄も同一構造のため同時に揃える(差分2行)。
2. **ドラッグ並び替えは ToDo にも横展開**。ToDo にはハンバーガーが無いのでドラッグハンドルを新設する形。

## 独立レビュー結果 (2026-07-26)

致命的 0 / 要修正 0 / 軽微 6、マージ可。軽微のうち3件(ハンドル見た目・\r・定数重複)は追補コミットで対応済み。残りは記録のみ:
- ドロップ直後、DB 書き込み完了前の極小ウィンドウで一瞬スナップバックし得る(直後の emit で自己修復)。
- reorder はアクティブ行のみ 0..n-1 に振るため、アーカイブ/ゴミ箱行の sortOrder と値が重複し得るが、復元は MAX+1 採番・アーカイブ一覧は ORDER BY 無しのため実害なし。
- 専用ハンドルは即時ドラッグ型(長押し不要)。ハンドル起点の縦スクロールは並び替えになる仕様。
- ハンドルは Workspace のスワイプ除外レジストリに未登録のため、ドラッグを横方向に流すとページングに奪われてドラッグが中断され得る(isReordering の固着は無し)。実機確認項目。

## 実機検証手順 (ユーザーの Mac でビルド後)

1. **文字統一**: ToDo のヘッダー/文字色/カード密度が Habit と揃って見えること(本文サイズは従来どおり)
2. **メモ折り返し**: ToDo/Habit の編集ダイアログで長いメモが4行まで折り返して見えること。改行キーやペーストで実改行が入らないこと
3. **ゴミ箱**: 背景が濃くなり下の一覧が読めなくなっていること。ゴミ箱表示中に下の一覧のタップ/長押し/ドラッグが一切反応しないこと。ゴミ箱内の復元/完全削除/戻るは正常なこと
4. **並び替え**: ハンドルのドラッグで並び替えられ、**再起動後も順序が維持される**こと。ドラッグ開始で展開カレンダーが閉じること。長押しメニュー(編集/アラーム/アーカイブ/削除)が従来どおり開くこと
5. **要注意**: ドラッグ中に横方向へ流したときの挙動(ページングに奪われないか)/ドロップ直後に一瞬順序が戻って見えないか
6. **回帰**: 草カレンダーの横スワイプ優先(前回修正)が引き続き効いていること
