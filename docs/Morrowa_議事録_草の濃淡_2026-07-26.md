# Morrowa 議事録: 草カレンダーの濃淡(達成率ベース) (2026-07-26)

統括: Claude (Fable 5) / 実装: Codex / レビュー: 独立サブエージェント

## 背景

年間草カレンダーは Bug3 修正(913e1e547b)で「1件でも完了があれば固定の緑」の二値表示になっていた。ユーザー要望により、GitHub 風に**その日の達成率で緑の濃さを変える**方式(b案)へ拡張する。

## 前提調査で確定した事実

- 頻度ルール(`habit_rules`)は `startDate`/`endDate` の**区間履歴**として既に保存されており、「その日どの頻度だったか」は遡って正確に分かる。ルール変更は旧ルールを閉じて新ルールを開く実装(setRule)。
- 過去のチェックは習慣別展開カレンダーから編集可能(未来のみ不可)。習慣定義の遡及編集は不可。
- 穴: (1) アーカイブは Boolean のみで時期の履歴なし、(2) 完全削除は CASCADE で履歴ごと消える、(3) setRule の日付が 4:00 境界でなく暦日。

## ユーザー決定 (2026-07-26)

1. **分母 = ルール履歴に忠実**: その日に有効なルールを持ち対象日だった習慣の数。ルール変更・習慣追加で過去の濃さは変わらない。アーカイブの時期問題は「アーカイブ時に現在ルールを閉じる/復帰時に再開する」で解決(**スキーマ変更なし**。fallbackToDestructiveMigration の地雷を回避)。
2. **週次/月次の習慣は対象日以外グレーアウトし、チェック操作を無効化**(一覧のチェックボタン、および習慣別カレンダーの対象外マス)。→ 対象外の日の完了はそもそも発生しなくなる。濃さの分子も対象日の完了のみ。
3. **濃さは連続**: 達成率(0〜1)を緑のアルファに直接マップ。完了ゼロの日は従来のグレー。
4. 付随決定(統括): ゴミ箱内の習慣は従来どおり全期間計算から除外(復元で復活)。完全削除で過去の濃さが遡って薄くなるのは仕様として許容。setRule / アーカイブのルール開閉の日付は `HabitDay.today()`(4:00 境界)に統一。分母0で分子0の日はグレー(決定2により分母0の完了は今後発生しない)。

## フェーズ計画 (1フェーズ=1コミット)

- **Phase A**: ルール開閉の整備 — setRule の日付を HabitDay.today() に統一 / アーカイブ時に現在ルールを閉じ、アーカイブ解除時に同内容で新ルールを開く
- **Phase B**: 濃淡表示 — ViewModel に日別達成率 `Map<String, Float>` の StateFlow(rules × completions × habits を combine、Kotlin 側で計算)。年間 GrassCalendar を達成率ベースの連続アルファに変更
- **Phase C**: 対象外日の無効化 — 一覧チェックボタン(今日が対象日でない習慣)と習慣別カレンダーの対象外マスをグレーアウト+操作無効
- **Phase D**: 独立レビュー → 追補 → 検証手順提示

## 追加要望 (2026-07-26, 実装中に受領)

- 習慣一覧の行タップは現在チェックが入るが、**編集ダイアログを開く**ように変更(チェックはチェック円のタップのみ)。ToDo(行タップ=編集)との一貫性もとれる。→ Phase C に組み込み。

## 独立レビュー結果 (2026-07-26)

要修正2件(追補コミットで対応済み)、軽微5件、コンパイル可能性・区間境界・重複排除・日付切替追従はすべて確認済み。

- **対応済み#1**: 修正以前にアーカイブ済みの習慣は開きっぱなしルールが残り分母に入り続ける → ViewModel 起動時に冪等バックフィル(`closeOpenRulesForArchivedHabits`)。旧バックアップ復元後も次回起動で自己修復。※バックフィルの endDate は実際のアーカイブ日ではなく実行日になる(アーカイブ日は記録が無いため近似)。
- **対応済み#2**: 対象外日の stray 完了が「緑なのに解除不能」→ 完了済みマスは対象外日でも解除タップのみ許可(統括判断: ロックアウトの趣旨は新規チェック防止。解除は一方向で、消すと対象外日には再チェック不可)。
- **決定#3**: アーカイブ当日はその日から対象外(endDate=当日、半開区間で当日除外)を仕様として維持。当日朝の完了は #2 により緑のまま解除可能。
- 軽微(記録のみ): チェック円上の長押しはメニューが開かない可能性(行の他部分で開くため実害小、実機確認項目) / ruleHistory 初回 emit 前の数フレームは対象外マスがタップ可能 / isTargetDay が日×ルールごとに JSON 再パース(習慣数十件なら許容、最適化は次回候補) / 1/1 0:00-4:00 の表示年ずれ(既存挙動、実害なし)。
- **残項目として発見**: `setRule`(頻度の後から変更)と `unarchiveHabit` / `getArchivedHabits` は**呼び出し元ゼロ** — 頻度変更 UI とアーカイブ解除 UI が未実装。機能としては土台だけ存在する。

## 実機検証手順 (ユーザーの Mac でビルド後)

1. **濃淡**: 習慣2つ(毎日)で片方だけチェック → 今日のマスが中間の緑(alpha 0.65)、両方 → 濃い緑、ゼロ → グレー。チェックのオン/オフでリアルタイムに濃さが変わること
2. **履歴忠実性**: 習慣を新規追加しても過去の日の濃さが変わらないこと。習慣をアーカイブすると翌日以降の分母から外れ、過去の濃さは不変なこと
3. **対象外日ロックアウト**: 週次習慣の対象外の日: 一覧のチェック円がグレーで押せない / 展開カレンダーの対象外マスが暗く押せない / 過去の対象日マスはトグル可能
4. **stray 解除**: (旧データがあれば)対象外日の緑マスをタップ → 解除できる、解除後は押せなくなる
5. **行タップ**: 習慣の行タップで編集ダイアログが開き、チェックはチェック円のみ。長押しメニュー・ドラッグ並び替え・カレンダー展開が従来どおり
6. **回帰**: 年間カレンダーの横スワイプ優先、4:00 日付切替、ToDo 側に変化がないこと
